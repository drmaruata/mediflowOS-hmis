# SaaS HMIS: Quality OS Indicator Specification

**Version:** 0.2 (draft) | **Status:** Source-aligned baseline | **Date:** 1 Oct 2026

This companion specification is the implementation baseline for the Quality OS. It is derived from the user-supplied `NQAS_Outcome_Indicator_final.xlsx` and `NABH Hospital Accreditation Standard 6th Edition January 2025.pdf`. Source wording is preserved where practical; whitespace is normalized for readability. Platform-generated IDs are unique per source row and do not replace the source sheet, serial number, standard reference, or page reference.

### 1.1 NQAS implementation rule

The earlier architecture note that exact NQAS parameters would be supplied later is superseded by this source baseline. The Quality OS shall load all 356 rows as catalogue definitions. The source-specific `Discharge Rate` indicators present in the workbook are retained even though a generic cross-framework discharge-rate KPI had previously been removed from the starter set.

### 1.2 NABH implementation rule

The supplied NABH 6th Edition contains a dedicated KPI section beginning at the book's printed page 202. It defines 32 organisation-wide KPIs and 18 department-specific KPIs. The source explicitly supports HIS/EMR capture where possible and manual numerator/denominator entry when the system cannot collate an indicator, and states that department-specific KPIs are generally captured from in-patients unless an indicator specifically mandates otherwise. The Quality OS therefore models each KPI as **auto, manual, or hybrid** and stores applicability/scope and sampling guidance.

## 5. Quality OS calculation contract

1. **Definition fidelity.** A framework-standard indicator is immutable after publication. A changed definition creates a new catalogue version; historical values retain their original definition version.
2. **Source precedence.** The active source definition controls numerator, denominator, population, unit, formula/operator, frequency, applicability and reporting lag. Generic helper calculations never override a source-specific definition.
3. **NQAS LAMA and absconding.** The NQAS KPI-sheet LAMA indicator is a **percentage** using LAMA cases × 100 ÷ admissions. The NQAS A&E Absconding Rate is **A&E-specific** and uses absconding cases × 100 ÷ A&E cases attended. These source definitions take precedence over any historical generic per-1,000 template.
4. **Discharge Rate.** Department/service-specific NQAS `Discharge Rate` indicators remain independent catalogue entries. The engine shall not collapse them into a generic cross-framework discharge KPI. Their source formulas determine the unit/operator.
5. **Bed occupancy / ALOS / BTR.** Bed-days use the source-defined midnight census convention where specified. ALOS uses the source-defined discharge population. For BTR, the catalogue retains the source denominator wording; where `functional beds` versus `total beds available` is ambiguous, implementation status remains `needs_product_owner_confirmation` rather than silently substituting a denominator.
6. **Calculation modes.** `auto` uses structured HMIS data; `manual` accepts source-defined numerator/denominator or count; `hybrid` combines system-derived components with audit/sampling inputs. Direct count, median and ratio indicators are not forced into a percentage model.
7. **Sampling.** Store sampling required/optional, method, population, sample size, observation period and evidence. NABH audit KPIs that specify stratified-random sampling shall retain that methodology.
8. **Frequency and lag.** The engine supports Monthly, Yearly, Continuous and cumulative/YTD reporting where specified. `reporting_lag_days` is source metadata and drives provisional/close behaviour.
9. **Applicability.** NQAS applicability follows source sheet and configured hospital/service scope. NABH department-specific KPIs are enabled only when the named specialty/service is in the tenant scope, unless the source marks the KPI optional and the hospital chooses to enable it.
10. **Provenance.** Store framework, edition, source document, content hash, source sheet/standard, source serial number, source page/locator and import timestamp.
11. **Data quality.** Every computed value carries `draft|provisional|locked|superseded|not_applicable` plus flags for missing inputs, invalid denominator, incomplete source events, insufficient sample, late data and calculation exceptions.
12. **Shared computations.** Two framework indicators may share one computation only when numerator, denominator, population, unit, frequency, applicability and definition semantics are equivalent. Similar names are insufficient.
13. **Reproducibility.** A locked value must be reproducible from its stored definition version and source inputs; corrections after lock create a new snapshot version with reason and approver.

## 6. Source governance

- NQAS source of truth for this baseline: `NQAS_Outcome_Indicator_final.xlsx` supplied in this project.
- NABH source of truth for this baseline: `NABH Hospital Accreditation Standard 6th Edition January 2025.pdf`, KPI section and related guidance.
- The NABH book is copyright-protected. The product team must confirm the right to reproduce indicator text/definitions in customer-facing screens and exports. This implementation catalogue should keep only the content needed for the licensed use case and retain source provenance.
- A future source revision never overwrites historical catalogue rows; it creates a new framework edition/source snapshot with an explicit migration note.

Quality OS domain events and manual forms then populate fact inputs; the indicator engine evaluates the versioned definition; snapshots feed dashboards, trends, alerts and CAPA.
